목표: 오토밴스처럼 **수리 한 건 = 페이지 한 장**을 꾸준히 쌓아, "모델 + 증상" 롱테일과 "마세라티 정비/수리/정비소" 브랜드 검색을 함께 잡는다.

## 1. 로건이 다른 점 (그릿·오토밴스와 비교)

| | 오토밴스(부산) | 그릿(파주) | 로건(파주) |
|---|---|---|---|
| 차종 | 수입차 전반 | 국산·수입 사고수리 | 마세라티·페라리만 |
| 고객 | 부산·경남 | 파주·일산·김포 | **전국 (탁송)** |
| 검색 중심 | 지역+브랜드+증상 | 지역+사고수리 | **브랜드+모델+증상** |

- 지역어는 보조. 제목에 "파주"는 넣되 맨 뒤 꼬리(`| 파주 로건서비스`)에만. 본문에 "전국 탁송" 1회.
- 대신 **모델명 + 증상 + 부품명**을 정확히 쓴다. 마세라티 오너는 "기블리 실화", "르반떼 서스펜션 경고"처럼 모델로 검색한다.
- 사고수리(판금·도장)는 로건 글로 쓰지 않는다. 그릿 사례로 넘기고 링크한다.

### 2-3. 카테고리 고르는 법
- 경고등·고장 증상의 **원인 찾기**가 이야기의 중심 → `diagnosis`
- 원인이 분명한 수리, 누유, 하체, 정기점검·소모품 → 브랜드별 `maserati` / `ferrari`
- 자동차보험으로 처리 → `insurance` / 성능보험으로 처리 → `warranty`
- 판금·도장 사고수리 → 로건 글 아님. 그릿에 사례로 올리고, 로건 글에서는 링크만.

| `seo_title` | 마세라티 {모델} {증상} 원인 — {작업} \| {카테고리 머리키워드} 파주 로건서비스 (60자 안팎) | 마세라티 기블리 엔진경고등·실화 원인 — 점화코일 교체 \| 마세라티 정비 파주 로건서비스 |

## 4. 본문 섹션 표준 (4~5개, 1,500~2,500자)

| 순서 | h2 예 | 들어갈 것 |
|---|---|---|
| 1 | 입고 증상 | 고객이 말한 증상 그대로, 언제·어떤 상황에서. 모델·연식·주행거리(아는 것만). 탁송 입고면 그 사실 |
| 2 | 진단 | 진단기 고장 기록, 확인 순서, 왜 그 부품을 의심했는지. 고장코드는 있으면 그대로 |
| 3 | 원인 / 작업 과정 | 원인 부품 사진, 교체·수리 내용, 같이 본 부위 |
| 4 | 출고 점검 | 시운전, 경고등 재확인, 고객에게 안내한 관리 포인트 |
| 5 (선택) | 이 증상이 있다면 | 오너가 스스로 확인할 수 있는 것, 방치하면 생길 일(일반 정보), 상담 방법 |

- 문단은 2~4문장. `**굵게**`는 섹션당 1번 이하.
- 각 섹션 첫 문장은 그 섹션의 결론(AI 발췌용).
- `faq` 2~3개: 그 모델·증상에 대해 오너가 실제로 묻는 말. 답은 2~3문장, 가격·기간 없이.
- 마지막 섹션 끝에 상담 안내 1문장(전화·카톡은 템플릿 버튼이 있으므로 문장만): "비슷한 증상이 있다면 경고등·계기판 사진을 카톡으로 먼저 보내 주세요."

## 5. 사진 규칙

- 한 글에 **실제 그 차 사진 6장 이상** 목표(입고 전체 1, 계기판 경고 1, 진단기 화면 1, 원인 부품 1~2, 작업 중 1, 출고 1).
- 번호판·고객 얼굴·차대번호·진단기 화면의 VIN은 가린다.
- 파일명: `assets/cases/{slug}-01.webp` 부터 순서대로. 가로 1600px 이하 webp.
- `alt`: 무엇이 찍혔는지 사실대로 ("마세라티 기블리 계기판 엔진경고등"). 키워드 나열 금지.
- `caption`: 사진에서 봐야 할 점 한 줄.
- 실제 사진이 없을 때 홈 사진(`assets/maserati-service-01.webp` 등)을 쓰면 반드시 "참고 사진"이라고 적는다. 실제 글 발행은 그 차 사진이 있을 때만.

## 7. 블로그(blog.naver.com/logan_service)용은 다르게

같은 사례·사진은 써도 되지만 **문장은 새로 쓴다**(중복 문서 방지).

| | 사이트 /cases/ | 네이버 블로그 |
|---|---|---|
| 말투 | 정비 기록, 건조한 사실문 | 사장님·정비사 1인칭, 대화체 ("오늘 들어온 르반떼는…") |
| 구조 | 섹션 4~5개 + FAQ | 사진 → 짧은 글 반복, 소제목 3~5개 |
| 제목 | 증상 원인 — 작업 \| 로건서비스 | "르반떼 에어서스펜션 경고, 한쪽이 내려앉는 이유 (파주 마세라티 정비)" 처럼 질문·호기심형 |
| 키워드 | 모델+증상 1~2회 | 제목 1, 본문 2~3, 태그 10개 안팎(마세라티정비, 르반떼수리 등) |
| 링크 | 관련 사례 자동 | 글 끝에 사이트 사례 링크 1개 + 전화·카톡 |
| 사진 | 6장 이상 | 10장 이상, 사진마다 한두 줄 |

블로그는 사이트 글 발행 후 1~3일 뒤 올린다(사이트가 원본으로 먼저 수집되게). 인스타·플레이스 소식에는 사진 3장 + 한 줄 + 사이트 링크.

## 8. 발행 주기와 내부 링크

- 주기: 주 2건 이상을 꾸준히(몰아서 수십 건보다 매주 일정하게). 재료가 쌓이면 주 3~5건.
- 비율: 마세라티 7 : 페라리 2 : 보험·성능보증 1 정도(입고 비율에 맞춤).
- `related`: 같은 모델 다른 증상 1개 + 같은 증상 다른 모델 1개 + 같은 카테고리 1개를 직접 지정. 없으면 자동.
- 본문 안 링크는 넣지 않는다(템플릿 버튼·관련 글로 충분). 예외: 사고수리 언급 시 "판금·도장은 그룹사 그릿서비스와 연계합니다" 문장과 함께 그릿 사례 목록(`site.yaml` group.cases)로 연결 — 개발자에게 템플릿 처리 요청.
- 사고로 입고됐지만 로건이 기계 쪽(냉각·하체·전장)을 맡은 경우: 로건 글은 기계 수리만 다루고, 판금·도장 부분은 그릿 사례 글로 따로 쓰고 서로 `related`/링크.
- 홈 "작업 사례가 곧 신뢰입니다" 섹션에 최근 사례 6개 조각 연결(개발자). FAQ의 "실제 정비 사례를 볼 수 있나요?" 답에 /cases/ 추가 요청.

## 9. 쓰지 말 것

- 가격, 수리비, 진단비, 수리 기간·소요 시간, 부품 대기 기간
- 대차, 24시간, 출장, 픽업 시간 약속

- "공식 서비스센터", "공식 협력", "정품 보증 유지" 같은 표현. 쓸 수 있는 말: "2016년부터 마세라티와 페라리만 전문으로 정비"
- 확인 안 된 탁송 금액. 탁송은 "전국 탁송 가능, 지역·정비 금액에 따라 탁송비 지원"까지만(자세한 구역은 홈 링크)
- 사고수리(판금·도장)를 로건이 직접 하는 것처럼 쓰는 문장
- 다른 정비소·딜러 비방, "센터보다 싸다"
- 실제 차가 아닌데 실제처럼 쓰기. 예시 글은 `draft: true` + 맨 위 주석
- 번호판·얼굴·VIN이 보이는 사진
- 영업시간을 쓸 때는 확인된 그대로만: 평일 09:00~18:00, 점심 12:30~13:30, 토·일요일 휴무

## 10. 발행 전 점검

1. `python3 -c "import yaml;yaml.safe_load(open('posts/{slug}.yaml'))"` 통과

4. 사진 alt 모두 있음, 번호판 가림
5. 사장님 확인 후 `draft: true` 삭제
