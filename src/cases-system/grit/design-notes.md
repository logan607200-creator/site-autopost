# 그릿서비스 수리사례 디자인 노트 (2026-10-22)

## 왜 이 배치인가
1. **결론을 맨 위에.** H1 바로 아래 "한눈에 보기" 박스에 summary 한 문장 + 차량/증상/작업 목록을 둔다. 구글·네이버 스니펫과 AI 답변이 그대로 가져가기 좋고, 손님은 3초 안에 "내 차 얘기인지" 판단한다.
2. **검색어 = 페이지 뼈대.** 빵부스러기(홈 > 수리사례 > 카테고리) → 카테고리 배지 → H1(증상+작업) → 날짜·차종·연식·주행거리·지역 메타 줄 → 번호 붙은 H2 섹션. 구조가 엔진의 BreadcrumbList·BlogPosting JSON-LD와 화면이 1:1로 맞는다.
3. **FAQ는 열린 상태로.** details에 open을 줘서 JS·클릭 없이도 질문·답이 그대로 보인다(FAQPage 데이터와 화면 내용 일치).
4. **전화로 이어지는 길이 세 겹.** 모바일은 하단 고정 전화(파랑)·카톡(노랑) 바, 데스크톱은 오른쪽에 따라오는 상담 박스(sticky, CSS만 사용), 본문 끝에는 차종 이름을 넣은 짙은 남색 CTA 박스("E클래스, 비슷한 증상이라면 사진부터 보내 주세요")를 둔다.
5. **끝까지 읽은 사람은 다음 사례로.** 비슷한 수리사례 카드 3장과 카테고리·전체 목록 버튼으로 내부 링크를 걸어 크롤링 깊이를 줄이고 체류 시간을 늘린다.
6. **목록은 진짜 링크.** 카테고리 칩은 모두 /cases/{slug}/ 로 가는 a 태그이고 JS 필터를 쓰지 않는다. 모바일 카드는 가로형(사진 38% + 제목)이라 한 화면에 4~5건이 보인다.
7. **홈과 같은 브랜드.** 검정 헤더와 흰 글씨, #004a9f, 모서리 없는 카드, Pretendard/Noto Sans KR, 본문 17px, keep-all을 쓴다. 회색 글씨는 #5b6270(흰 바탕 대비 약 6:1)으로 올려 AA를 맞췄다.
