# 그릿서비스 수리사례 글쓰기 가이드

2026-10-22. 이 문서는 `posts/*.yaml` 를 쓰는 사람(마케터·AI)이 따를 규칙입니다. 형식은 `../SPEC.md`, 사이트 정보는 `site.yaml` 이 기준입니다.

원칙 한 줄: **수리 한 건 = 페이지 한 장 = 검색어 하나.** 고객이 실제로 치는 말(차종 + 부위·증상 + 작업 + 지역)을 제목에 넣고, 본문은 우리가 직접 본 사실만 씁니다.

---

## (a) 키워드 지도

수치 = 네이버 검색광고 키워드도구 월 검색량(PC+모바일), 2026-10-20 실측 (`marketing-review/그릿-네이버키워드-20261020.md`). "10 미만" = 사실상 검색 없음. 수치 없는 것은 측정 안 함.

**읽는 법:** 사고 난 사람은 "파주사고수리"(10 미만)가 아니라 **파주공업사(200)·파주카센터(300)** 로 찾습니다. 큰 단어는 스마트플레이스와 description·tags 에 쓰고, 사례 글 제목은 **차종 + 부위 + 작업** 롱테일로 승부합니다. 블로그 문서가 수만 건이라 큰 단어 하나로 1페이지는 어렵습니다.

| 카테고리 | 대표 검색어 (월 검색량) | 본문·태그에만 (10 미만) | 롱테일 예 (차종 × 부위 × 지역) |
|---|---|---|---|

| 판금·도색 painting | 파주판금도색 60, 일산판금도색 80, 파주덴트 100 | 파주판금, 파주자동차판금, 운정판금도색, 파주문콕 | 파주 K5 문콕 덴트 / 운정 아반떼 범퍼 긁힘 부분도색 / 금촌 카니발 슬라이딩도어 판금 |

- 세차(파주손세차 1,240 · 파주세차장 360 · 운정세차 240)는 그릿 프리미엄 세차가 손세차일 때만 씁니다. 사장님 확인 전에는 쓰지 않습니다.
- 수입차 사례는 카테고리가 아니라 **차종명**(벤츠·BMW·아우디…)과 태그 "파주수입차정비"로 묶습니다. 기존 `/imported-cars/` 페이지로 내부 링크합니다.
- 지역어는 site.yaml `regions` 안에서만: 파주, 운정, 교하, 금촌, 문산, 일산, 김포.

## (b) 제목·설명·요약·slug 공식

| 필드 | 공식 | 길이 |
|---|---|---|
| `title` (H1) | {모델} {사고·증상} {부위} {작업} | 15~30자 |
| `seo_title` | {브랜드} {모델} {부위} {증상} {작업}·{작업2} \| 파주 그릿서비스 | 60자 안팎 |
| `description` | {차종}의 {증상}을 {진단}해 {작업}한 과정. + 지역어 1회 + 무엇을 볼 수 있는지 | 80~120자 |
| `summary` | 결론 먼저: "{차종} {증상}은 {원인/손상}이었고, {조치}로 수리했다." + 고객이 알아둘 사실 1개 | 1~2문장 |
| `slug` | {YYMMDD}-{브랜드영문}-{모델영문}-{작업영문} (소문자, 하이픈) | 입고일 기준 |

좋은 예 / 나쁜 예

- title — 좋음: "GV70 주차장 접촉사고 앞범퍼 교환·도색" / 나쁨: "고객님 차량 수리 완료!" (차종·부위 없음), "Genesis GV70 Front Bumper" (영어 H1)
- seo_title — 좋음: "제네시스 GV70 앞범퍼 접촉사고 교환·도색, 센서 점검까지 | 파주 그릿서비스" / 나쁨: "파주공업사 파주카센터 파주판금도색 최고 그릿서비스" (단어 나열, 과장)
- description — 좋음: "주차장에서 앞범퍼가 깨진 제네시스 GV70. 범퍼 안쪽 보강재와 주차 센서를 점검하고 범퍼 교환·도색 후 출고한 과정을 파주 그릿서비스가 사진으로 정리했습니다." / 나쁨: "최고의 기술력으로 완벽하게 수리했습니다." (사실 없음)
- summary — 좋음: "앞범퍼 커버는 깨졌지만 보강재와 센서 브래킷은 이상이 없어 범퍼 커버만 교환하고 조색해 도색했습니다." / 나쁨: "이틀 만에 저렴하게 끝냈습니다." (기간·가격 = 확인 전 숫자)
- slug — 좋음: `261015-genesis-gv70-front-bumper` / 나쁨: `case1`, `261015-제네시스-범퍼`, `accident-repair` (카테고리 slug 와 겹침)

## (c) 섹션 구성 표준 (H2, 4~5개)

**사고수리·판금도색·보험수리용**
1. 입고 상태 — 언제·어떻게 난 사고인지, 눈에 보이는 손상 (차종·연식·주행거리는 아는 것만)
2. 손상 진단 — 범퍼를 뜯어 본 안쪽(보강재·브래킷·센서·하체), 교환 vs 판금 판단 근거
3. 작업 과정 — 탈거 → 판금/교환 → 퍼티·프라이머 → 조색 → 도색 → 조립 순서. 보험이면 접수·협의 단계
4. 출고 점검 — 단차·색 맞춤·센서·경고등 확인 결과
5. (선택) 고객이 알아둘 점 — 도색 후 관리, 보험 처리 시 준비물 등 일반 정보

**정비용 (성능보증수리 포함)**
1. 입고 증상 — 고객이 말한 증상 그대로 ("브레이크 밟을 때 끽 소리")
2. 점검·진단 — 확인한 항목과 결과 (측정했다면 측정값, 고장코드는 코드 그대로)
3. 원인 — 왜 그런 증상이 나는지 한 문단
4. 작업 내용 — 교환 부품, 작업 순서
5. 출고 점검·관리 안내 — 시운전 결과, 다음 점검 시점(업계 일반 기준으로만)

**외형관리·PPF용**
1. 입고 상태·고객 요청 — 신차/중고, 걱정하는 부위
2. 도장면 점검 — 스월·스크래치·오염 상태
3. 준비 작업 — 세척·탈지·(필요하면) 광택
4. 시공 과정 — 범위, 재단·마감 방식
5. 출고·관리 안내 — 시공 후 세차·관리 일반 수칙

## (d) 사진 규칙

- **장수:** 글당 6~15장 권장(최소 4장: 입고 전체, 손상 근접, 작업 중, 출고). 표지(`cover`)는 차종이 보이는 출고 사진.
- **파일:** `assets/cases/{slug}-01.webp` 부터 순서대로. 가로 1600px 이하, 장당 150KB 아래.
- **alt 공식:** "{차종} {부위} {상태/작업} {장면}" — 예: "제네시스 GV70 앞범퍼 깨짐 입고 상태", "도장 부스에서 조색 후 도색하는 GV70 앞범퍼". "사진1", "IMG_2031", 키워드 나열 금지.
- **caption:** 사진이 말해 주는 사실 한 줄 ("범퍼를 뜯어 보니 보강재는 휘지 않았습니다").
- **번호판:** 모든 사진에서 가린다(모자이크·스티커). 고객 얼굴, 차 안의 서류·하이패스·블랙박스 화면, 다른 고객 차 번호판도 가린다.
  - 주의: 지금 사이트 사진 중 `grit-repair.webp`, `grit-bay.webp` 는 흰색 벤츠 번호판이 보입니다. 사례 글에 쓰려면 가린 버전을 새로 만들어야 합니다.
  - `grit-care.webp` 의 GV70 번호판은 대표번호(1577-0412)와 같은 장식 번호판으로 보입니다. 실제 등록 번호판이 아니라는 것을 사장님께 확인한 뒤 씁니다.

## (e) 사장님이 줄 재료 (카톡으로 사진 + 메모 5줄이면 끝)

**사진 (휴대폰 세로·가로 상관없음)**
- [ ] 입고 때 차 전체 1장 (앞 또는 뒤 사선)
- [ ] 손상 부위 가까이 2~3장
- [ ] 뜯어 본 안쪽 / 리프트 위 하체 / 교환한 부품 1~3장
- [ ] 작업 중 (판금·부스·조립) 1~3장
- [ ] 출고 때 같은 각도 1~2장
- (번호판은 저희가 가립니다. 고객 얼굴만 안 찍히게)

**메모 (아는 것만, 모르면 비워두기)**
1. 차종·연식·주행거리 (예: 그랜저 IG 2019 / 8만km)
2. 무슨 일로 왔나 (예: 주차장 후진 중 기둥에 박음, 운정 고객)
3. 뜯어 보니 / 점검해 보니 (예: 보강재 휨, 센서 정상)
4. 한 작업 (예: 리어범퍼 교환, 트렁크 판금, 조색 도색)
5. 보험 여부 (자차/대물/성능보증/일반) 과 고객 게시 동의 여부

## (f) 같은 사례의 블로그 글은 이렇게 다르게

| | 사이트 사례 페이지 | 네이버 블로그 글 |
|---|---|---|
| 목적 | 검색·AI가 발췌할 기록 | 네이버 블로그 탭 노출, 이웃·지역 독자 |
| 제목 | 차종+부위+작업 \| 파주 그릿서비스 | 메인 키워드 1 + 보조 2 ("파주공업사 판금도색 후기, 운정에서 오신 GV70 앞범퍼") |
| 말투 | 짧은 단정문, 사실 위주 | "~하셨어요", 대화체, 현장 이야기 (예: `geo/blog/01-사고수리-QA.md` 처럼 "기본이 가장 중요합니다. 그릿서비스였습니다."로 맺음) |
| 구성 | 요약 박스 → H2 4~5개 → FAQ | 도입(고객 상황) → 사진 많이 + 짧은 설명 → 상담 안내 블록 |
| 문장 | **같은 문장 복붙 금지.** 사진·사실은 같아도 됨 | 사이트 글을 다시 써서 표현을 바꿈 |
| 링크 | 블로그로 링크 안 해도 됨 | 끝에 사이트 사례 페이지 주소 1개 |

블로그 비율은 기존 방향대로 작업기 : Q&A = 7 : 3. 같은 사례로 플레이스 소식(사진 3장 + 2줄)도 함께 올립니다.

## (g) 발행 주기·내부 링크

- **주기:** 처음 한 달은 주 3건 이상(사진 있는 건 전부), 이후 주 2~5건. 하루에 몰아 올리기보다 입고·출고 흐름대로 꾸준히. 오토밴스는 석 달에 사례 187장을 쌓았습니다(참고일 뿐 목표 수치 아님).
- **카테고리 균형:** 검색량이 큰 정비(카센터)와 사고수리를 우선, 외형관리는 시공이 있을 때.
- **내부 링크 규칙**
  - 글마다: 같은 카테고리 목록(`/cases/{category_slug}/`) + 그 서비스 상세 페이지(site.yaml `service_page`, 예 `/accident-repair/`) 1회.
  - `related`: 같은 차종 또는 같은 부위 글을 우선 2~3개. 비우면 같은 카테고리 최근 3개가 자동으로 붙음.
  - 수입차 사례는 `/imported-cars/` 로 1회, 질문형 내용은 `/faq/` 로 1회.
  - 홈 "최근 수리사례" 6개 → 목록 → 글 → 목록/서비스 페이지로 막힘 없이 오가게.
  - 링크 문구는 "파주 사고수리 안내" 처럼 내용이 드러나게. "여기", "클릭" 금지.

## (h) 쓰면 안 되는 것

- **확인 전 숫자:** 가격·견적 금액, 수리 기간("당일 출고", "2일"), 영업시간·"24시간", 대차 제공 여부, 누적 실적("○○대 수리"), 보증 기간. 사장님이 확인해 준 값만, 확인 후에도 해당 글에 한해서.
- **그릿 고유 수치 대신 업계 일반 정보만:** "도색 후 2~4주는 자동세차를 피하라고 안내하는 경우가 많습니다"처럼 일반적임을 밝혀 씁니다.
- **과장·비교:** 최고, 최저가, 완벽, 100%, 새 차처럼 감쪽같이, 1급(확인 전), 정품(부품 출처 확인 전), 다른 업체 비하.
- **보험 관련 약속:** "자기부담금 없음", "보험료 안 오름", "보험사보다 더 받아 드림" 같은 표현.
- **개인정보:** 번호판, 고객 이름·얼굴, 상세 주소(지역은 "운정" 수준까지).
- **실제가 아닌 사례를 실제처럼 공개하기:** 예시 글은 반드시 `draft: true` 이고 파일 맨 위에 `# 예시 글: 실제 사례 아님`.
- **검색엔진용 문구:** "검색 유입을 위해", 같은 키워드 반복 나열, 숨김 텍스트.
